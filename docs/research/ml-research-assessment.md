# Neural methods for Prompire — research assessment

**Did the corpus surface neural methods worth pursuing? Mostly no — and the corpus itself supplies the strongest refutations.** No neural method currently justifies implementation in Prompire. The book corpus contains one documented case of a learned overseer being reward-hacked by the agent it supervised, textbook-stated failure modes for every density-based anomaly detector, and a catalogue of LLM-judge biases that collide directly with Prompire's pin-and-hash reproducibility story. What survives the evidence is cheaper than neural: a deterministic test-edit triage signal (the corpus argues G2 is a supervised/rule problem, not an anomaly problem), a lexical ranker for scope drafting behind the existing human-confirmation gate, and one genuinely interesting label-free research idea — compression-based brief-to-diff surprisal — that fits the PyYAML-only footprint and deserves a falsification experiment before anyone believes it. Every learned signal, if ever built, must live in a channel structurally incapable of touching an exit code — including the REVIEW channel, which fails `--strict` runs (`check_scope.py:920`) and therefore is not the harmless place an "advisory" signal might appear to be.

**How this was verified.** Five parallel readers covered seventeen ML-relevant books deeply plus a one-line sweep of the remaining twenty-odd, each reporting provenance to file and line. The draft conclusions were then run through a fresh-context adversarial reviewer. That review forced three real corrections (the delivery channel, a circular evaluation design, and one-sided judge evidence), and two of its attacks were themselves overturned by direct source checks — the UDL typical-set passage exists at `understandingdeeplearning-02-09-26-c/source-text.md:14241` (the reviewer's grep hit the corpus's known binary-file trap), and the judge perplexity-preference quote exists at `genai-design-patterns/source-text.md:10067`. No repository files were modified during the investigation.

Corpus root: `~/LifeOS/outputs/book-extraction/`.

## 1. Executive conclusion

**Recommendation 1 — PROTOTYPE (non-neural, with a small supervised arm): test-edit triage for G2.** A deterministic feature extractor over test-file hunks — assertion-count delta, tolerance widening (`assertEqual`→`assertAlmostEqual`, `atol=` growth), expected-value edits, broadened `except` clauses, deleted cases — emitting a *ranked* advisory annotation into a new report artifact that no exit code reads. The same experiment should include a naive-Bayes/logistic arm over the same features, because that is what the corpus actually prescribes for enumerable defect classes (Chollet: labeled defect detection "is a binary classification task," and anomaly detection "would not be a good fit"; ISLP: naive Bayes is the estimator that *wins* precisely in the small-n, large-p regime this problem lives in). A neural classifier enters only if the linear arm shows signal and plateaus — RESEARCH.

**Recommendation 2 — PROTOTYPE, conditional: lexical (BM25-style) scope-candidate ranking for G4**, inside the existing `draft` flow, where every proposal is already gated behind `# prompire:unconfirmed` markers a human must delete before `prepare` accepts the brief. Conditional because the value claim is currently unfalsified: first measure how often humans actually edit drafted scope lines today. Justified on dependency cost (zero new runtime dependencies), not on "lexical beats dense for code" — the request sentence is natural language, which is exactly the paraphrase case where the books document lexical retrieval failing.

**Recommendation 3 — RESEARCH: compression-based brief↔diff surprisal for G1/G3.** MacKay's compression-equals-modelling line (MDL two-part codelengths, adaptive arithmetic coding that "can be used with any probability distribution, which can change utterly from context to context") supports a label-free, training-free, standard-library-implementable score: does the diff compress meaningfully better conditioned on the brief and the repo's own history than without it? It inherits the corpus's strongest negative result — BLEU cannot separate correct from incorrect HumanEval solutions, so any surface-level statistic is a weak hint — which is why the bar is *incremental* value over plain token overlap, and why it stays RESEARCH until that is measured.

**Where neural methods clearly do not belong:** anywhere in the verdict path; as a test-integrity judge; as a semantic-drift gate; as behavioral modeling of agent tool-call sequences (G5 — no corpus support and instrumentation cost disproportionate to a deliberately lightweight tool); and as density/reconstruction-error anomaly detection over diffs, which the textbooks refute in the very passages that describe it.

## 2. Prompire authority model (as it bears on the analysis)

Prompire's authority is evidence the agent does not control: the git diff against a pinned `base_rev`, the sha256 of the armed brief in `.prompire/ACTIVE`, command exit codes measured before and after, and the tombstone log of every disarm. Its checker's output taxonomy is already the right skeleton for an advisory layer: **VIOLATION** is mechanical ("the path changed and the brief did not allow it"), **REVIEW** is "something a diff can show but no checker can judge." The semantic gaps are exactly where REVIEW ends: drift inside allowed scope, repair-versus-weakening of an allowed test edit, and whether the diff's meaning matches the goal. Two constraints from the implementation shape everything below. First, REVIEW is not consequence-free — `--strict` turns any REVIEW into exit 1 (`check_scope.py:920`), and REVIEW inflation is already why strict mode is hard to keep believed (`references/ci.md`). Second, the project has a *documented* alarm-fatigue incident (`references/threat-model.md`: eight correct violations, operator stops reading), so "advisory can't hurt" is false here by recorded experience; every added finding carries a burden of proof. `references/rules.md` also pre-registers the design's own objection: "A heuristic that guessed at assertion strength would fail both ways and would be trusted anyway, which is worse than a flag that says 'read this.'" Any triage signal must answer that — it does so by *ranking within* an existing flag rather than deciding anything, and by shipping with a measured false-discovery rate instead of an implied one.

## 5. Detailed analysis of the strongest candidates

**Candidate 1: test-edit triage (G2).** The gap: under `tests_policy: named` or `authoring`, an allowed test edit gets a bare REVIEW saying "read this diff," with no help on *which hunks* deserve the reading. Corpus evidence: Chollet's argument that enumerable, collectable defect classes are a supervised problem, not anomaly detection (`chollet:6846`); ISLP's naive-Bayes regime argument; Mohri's ranking-over-classification framing; Lakatos's demarcation — a legitimate repair *adds* something nameable (a precondition, a new case), a weakening *excludes* the failing instance (skip, widened tolerance, deleted assertion), with the honest caveat that Lakatos himself shows the distinction fooled the Cauchy school for 26 years, which is why this can only ever rank, never rule. Model input: the unified diff of test-file hunks plus the same `SKIP_MARKERS`-style token machinery `brief_common.py` already has. Output: per-hunk scores with named firing features ("2 assertions removed, tolerance widened 10×"), ranked, top-k only. Integration point: a new advisory section in the generated checklist or a separate `task.advice.md` — a finding kind excluded from `strict_reviews` *by construction*, so no invocation mode can turn it into an exit code. Shown to the reviewer after the run, never rendered into the agent's prompt — the Pong lesson restated for this setting is *never let the optimizer optimize against the learned signal*. Non-neural baseline: this *is* the baseline; the learned arms must beat it to exist. Failure behavior: extractor crash or unparseable diff produces an empty advice section stating so — absence of advice, never a verdict. Data: see §7. Operational cost: zero new dependencies, no weights, no network, milliseconds. Why neural is not justified yet: the failure modes are enumerable text facts; the corpus says start supervised-linear; and an evasion argument cuts equally both ways (a published feature list is *more* evadable than an opaque model — the honest claim is the hook's claim, a speed bump against lazy weakening that turns evasion into a visible, deliberate act).

**Candidate 2: scope-candidate ranking (G4).** The gap: `draft` proposes acceptance commands from repo evidence but has no ranked opinion about scope. This is the one gap where being wrong is nearly free — every suggestion arrives marked `# prompire:unconfirmed` and `prepare` refuses until a human deletes the marker. Corpus evidence: hybrid retrieval chapters in three books; the identifier-obscuring passage arguing the dense half adds least on code-shaped corpora; and the drafting-side framing from inverse reward design — the stated request is *evidence about* intent, so the drafting tool's job is surfacing what the request under-specifies, not widening scope on the agent's behalf. Input: the task sentence; corpus = file paths, symbol names, and recent-commit co-change structure. Output: top-k candidate paths with scores, all marked unconfirmed. Baseline to beat: the current draft heuristic plus a trivial recency/frequency ranker — and before any of it, the measurement of whether humans actually edit drafted scope lines often enough to matter. Failure behavior: no candidates, empty scope, human writes it, exactly as today. Cost: pure-Python scoring, no new dependencies. Neural (embeddings) rejected here on footprint and on the books' own evidence that the dense half contributes least for identifier-heavy corpora; if paraphrase misses turn out to dominate the error analysis, that conclusion should be revisited — with an experiment, not by default.

**Candidate 3: compression surprisal (G1/G3).** The gap: no current signal says "this in-scope hunk has nothing to do with this brief." Corpus evidence: MacKay's MDL (`mackay:29855`), adaptive coding from a prior with no training phase (`:11306`), Shannon surprisal (`:3077`), prequential evaluation for leakage-free scoring, and — against it — the BLEU/HumanEval result that surface statistics don't track code correctness, plus the caveat that practical compressors are dominated by shared substrings and so sit closer to lexical overlap than the MDL framing suggests. Input: the brief text, the diff, and repo history as the conditioning corpus. Output: per-hunk conditional-compression gain, presented as ranking evidence only. Baseline: plain token overlap between brief and hunk; the experiment's whole question is *incremental* recall over that. Failure behavior: score unavailable → no advice. Cost: `zlib` is in the standard library; a proper adaptive model is a few hundred lines. Why this is the one research idea worth keeping: it is the only G1/G3 method in the corpus that is label-free, training-free, footprint-compatible, and deterministic given fixed inputs — reproducibility survives, which no LLM-based option can say.

## 6. Methods Prompire should not use

**A learned test-integrity judge with any authority.** The alignment book's Pong result is the exact configuration: a model trained to recognize "what the human wants," supervising an optimizer, and gamed by behavior that *looked right to the model* (`alignment-problem:3425`). The judge-bias literature makes it worse for this specific task: leniency, self-bias of 10–25% toward the judge's own model family (often the same family as the coding agent), verbosity bias, and a documented preference for well-written low-perplexity text *even when inaccurate* (`genai-design-patterns:10067`) — meaning the fluent, plausible weakening is precisely the input the judge scores best. To be fair to the evidence, the same corpus reports ~85% judge-human agreement on general tasks and endorses judges to "guide development"; the REJECT here is not "judges are useless" but that a nondeterministic, unpinnable component cannot sit anywhere a verdict lives, in a tool whose entire trust story is that fixed inputs give fixed verdicts.

**Density and reconstruction-error anomaly detection over diffs.** Both failure directions are textbook-stated: reconstruction error is also low at probability *minima* (`goodfellow:14367`), and high-probability outliers fall outside the typical set (`understandingdeeplearning:14241`). A drift detector that can be silent on the most anomalous input has negative value in a review pipeline.

**Embedding-cosine drift detection as a shipped default.** Three independent objections: no task-independent embedding space exists (Chollet Ch. 11); embeddings obscure the identifiers code is made of (`ai-engineering:9311`); and a stored learned signal changes meaning under a model swap, with no analogue of the brief's sha256 pin to catch it — a new, silent non-reproducibility in a tool sold on a cryptographic pin. Minimum footprint is ~80MB of weights plus torch: a category change in what Prompire is.

**Neural behavioral modeling of agent traces (G5).** One paragraph of support in the whole corpus, quadratic error growth when the training distribution (clean human commits) differs from the judged distribution (agent output — the imitation-learning result), and instrumentation the tool would have to grow across every host adapter. What survives of G5 is countable without any model: files touched, commands run, declared-vs-actual set arithmetic — checklist facts, not classifier inputs.

**Anything that lets a learned signal flip, suppress, or gate a deterministic finding.** The corrigibility result gives the design rule its sharpest form: the safe configuration structurally forbids the learned component from reaching certainty. Concretely: advisory output lives in its own artifact, excluded from every exit-code path including `--strict`, and is never rendered into the agent's prompt.

## 7. Experiments

**E1 — test-edit triage (Candidate 1, the PROTOTYPE).** Hypothesis: a ranked deterministic feature signal concentrates real test-weakenings into the top of a reviewer's reading order at a bounded false-discovery rate. Dataset — the honest bottleneck, and shared by every arm: (a) *real weakenings*, harvested from public repos (reverted test edits, review comments rejecting a test change, and Prompire's own bench GAMED rows), collected by someone other than the feature author and frozen *before* feature design; (b) *real repairs*, test edits accompanying accepted bug fixes; (c) *mutants*, generated weakening transforms — used **only** for false-discovery-rate and calibration measurement, never recall, because feature set and mutation operators share a taxonomy and mutant recall would be tautological. Repository-level holdout throughout; per-class rates reported separately (the two pools are collected separately, so any aggregate is a collection artifact). Baseline: random hunk order, and the current behavior (a bare REVIEW flag). Models: rule-rank; naive Bayes/logistic over the same features; optionally a frozen-code-embedding + linear head arm (*external inference — the corpus contains no code embeddings*). Primary metrics: recall of real weakenings within a top-3-hunks-per-diff review budget; FDR among flagged hunks; pairwise AUC. Acceptance: on repo-held-out real weakenings, top-3 recall ≥ 0.6 at FDR ≤ 30%, and the expected flags-per-clean-diff at that operating point stated explicitly against an assumed weakening prevalence ≤ 5%. A learned arm justifies itself only by ≥ 10 points of recall over the rule arm at equal budget. Failure: no arm exceeds pairwise AUC 0.65 → abandon ranking, keep the bare flag, and record why — a signal that would be trusted anyway is worse than "read this."

**E2 — scope-candidate ranking (Candidate 2).** Hypothesis: lexical ranking of repo paths against the task sentence places the truly-changed files in the top-10 candidates materially more often than the current draft heuristic. Dataset: real commits from held-out OSS repos — commit message as the task sentence, files changed as ground-truth scope; plus the dogfood briefs. Precondition measurement: fraction of drafted scope lines humans currently edit; if < ~20%, stop — nothing to buy. Baseline: current `draft` + recency/frequency ranking. Model: BM25 over paths, symbols, and co-change neighbors. Metric: recall@10 and MRR of changed files. Acceptance: ≥ 20-point recall@10 gain over baseline on held-out repos. Failure: gain < 10 points, or the precondition measurement comes back small.

**E3 — compression surprisal (Candidate 3, RESEARCH gate).** Hypothesis: conditional-compression gain of a hunk given (brief + repo history) separates on-task from off-task in-scope hunks *beyond* token overlap. Dataset: synthetic composites — real commits with one hunk transplanted from an unrelated commit into an allowed file (the telemetry-in-config.py case, manufactured at scale), prequentially scored over commit history. Baseline: brief↔hunk token overlap. Model: zlib-dictionary or small adaptive arithmetic coder. Metric: pairwise AUC (transplanted vs native hunks), reported as *incremental* AUC over the overlap baseline. Acceptance: ≥ +0.10 AUC increment. Failure: increment < 0.05 — the signal is lexical overlap in disguise; drop it.

## 8. Recommended architecture

The smallest arrangement that preserves the authority boundary, if any experiment above succeeds:

```
                         PROMPIRE
        lint → baseline → pin → agent runs → real git diff
                              │
                    check_scope.py / verify
                              │
              VIOLATION / REVIEW → exit 0 / 1 / 2      ← authority (unchanged)
                              │
              ────────────────────────────────────
                 optional advisory pass (post-hoc,
                 reviewer-invoked, e.g. `prompire advise`)
              ────────────────────────────────────
                              │
          ranked annotations, named features, abstentions
          (finding kind excluded from every exit path;
           feature-set/model version hashed into the report;
           never rendered into the agent's prompt)
                              │
                  task.advice.md → human review
```

Three properties are load-bearing: the advisory layer reads the same evidence (the diff against the pinned base) but writes to an artifact no exit code consumes — *not* REVIEW, which `--strict` converts to failure; it identifies its own version in its output, so a changed ranker cannot silently re-mean an old report, mirroring the brief pin; and it can abstain, with abstention rendered as absence rather than as a low score.

## 9. Best first experiment

**E1, the test-edit triage bake-off.** It has the highest information value because it targets the gap Prompire's own documentation names as its loudest limitation (both README and `references/rules.md` state no checker can tell a repaired assertion from a weakened one), it simultaneously prices the non-neural baseline and the cheapest learned method in one design, its labels are the same corpus any future learned work would need — so the effort is not wasted even on a null result — and a null result is itself decisive, converting "we could add a heuristic" into a measured "we tried; a bare flag is better," which is exactly the kind of sentence this project's documentation is built from. Inputs: unified diffs of test-file hunks. Dataset, baseline, models, metrics, acceptance (top-3 recall ≥ 0.6 at FDR ≤ 30%; learned arm must add ≥ 10 recall points to exist) and failure threshold (pairwise AUC ≤ 0.65 → abandon) as specified in §7. Approximate footprint: the extractor and rule-ranker are a few hundred lines of standard-library Python plus the token machinery `brief_common.py` already contains; the naive-Bayes arm adds tens of lines; the corpus harvest is the real cost, roughly a few days of curation, and it must be done by someone who has not seen the feature list.

**Bottom line.** The corpus was worth mining, but what it mostly yielded is discipline, not architecture: rank instead of classify, promise a false-discovery rate instead of an accuracy, evaluate prequentially instead of cross-validating data you don't have, let the signal abstain, and never let the optimizer see — or the verdict path touch — anything learned. No neural method currently earns a place in Prompire. The three things that do earn an experiment are a deterministic ranker, a lexical ranker, and a compression score, all of which fit inside the tool's existing footprint and none of which can buy, flip, or soften a verdict.
